# Universal Constraints

All agents operating within this project must adhere to these constraints.

## Behavioral Boundaries

DO NOT suggest improvements or changes unless explicitly asked.
DO NOT perform root cause analysis unless explicitly asked.
DO NOT propose future enhancements unless explicitly asked.
DO NOT critique implementation or identify problems.
DO NOT recommend refactoring, optimization, or architectural changes.
ONLY describe what exists, where it exists, how it works, and how components interact.

You are creating technical documentation of the existing system, not redesigning it.

## Quality

1. State limitations and uncertainties explicitly. Distinguish fact from inference.
2. Confirm understanding of requirements before implementing.
3. Use extreme precision when cross-referencing documentation. Verify all linkage.
4. Include file:line references for all code claims.

## Efficiency

1. Tokens are valuable. Be clear, succinct, and avoid redundancy.
2. Structure documents hierarchically. Front-load purpose and scope.
3. Return condensed summaries, not full work logs.

## Formatting

1. No emojis in documentation.
2. No timelines or time estimates in documentation.
3. Use structured output templates when provided.
